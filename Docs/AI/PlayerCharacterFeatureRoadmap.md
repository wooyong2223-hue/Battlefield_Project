# 캐릭터 기능 전체 구현 목록 — 2026-10-28 갱신

기본 이동 디테일 2차: 공개 배틀필드 보병 영상의 실제 프레임을 참고해 가속/제동·공중 방향 제어, 실제 속도 기반 걷기/달리기 블렌드, 1인칭 보행 카메라/롤·착지·무기 관성·달리기 자세·ADS 팔 위치 블렌드를 추가했다. 기존 3인칭 구도/최고 속도/입력은 유지한다. 제품 전체 107/107 + 이후 추가 더미 검사 1/1, 별도 렌더 10/10 통과. 전용 동작 모션·3인칭 상체 달리기·제자리 회전·발 접지 및 조준/반동 세부 구현은 남아 있다. [이번 파일·설정·영상·검증 기록](PlayerCharacterBattlefieldMotionChanges.md).

최신 사용자 방침: **하나씩 단계별로 구현하고 디테일을 확인한다.** 진행 순서는 기본 이동 → 조준/반동 → 앉기/포복 → 특수 이동 → 전투/소생이다. 현재 기본 이동 1차로 서 있는 상태의 뒤걷기/좌우/대각선 모션과 정지 시 방향 유지가 연결됐다. 가속/감속·제자리 회전·발 접지는 아직 남아 있다. [정확한 파일·값·검증 기록](PlayerCharacterLocomotionDetailChanges.md)을 참조한다. 방향 회귀 3개를 추가한 제품 PlayMode는 98/98 통과했다.

사용자는 조준만이 아니라 캐릭터 기능 전반을 배틀필드처럼 구현하도록 요청했다. 이 문서는 그 전체 요청의 진행 목록이다. 일부 항목이 통과했다고 전체 구현 완료로 간주하지 않는다.

최신 보병 통합에서는 포복·슬라이딩·낮은 장애물 통과·기울이기·윗면 무기 거치·실제 조준 반동·다운/출혈/마무리 피해·소생/끌기·리스폰과 HUD를 추가했다. 현재 사용자 씬의 체력 100 및 별도 탄창/근접 오브젝트 구조를 유지한다. 전용 모션과 나머지 기능은 미완료다. 정확한 파일·수치·검증과 테스트 메뉴는 [보병 기능 확장 보고서](PlayerCharacterInfantryChanges.md)를 참조한다.

## 기준과 범위

배틀필드 6의 공개된 플레이 동작을 참고하되, 기존 프로젝트의 1·3인칭 전환, Alt 자유 시점, 우클릭 유지 견착/탭 ADS와 승인된 수치는 현재 기준으로 보존한다. 공식 자료는 플레이 동작을 설명하며 내부 소스·본 가중치·리깅 구현을 입증하지 않는다. 아래 구현 순서와 책임 분리는 이 프로젝트의 설계안이며 배틀필드의 내부 설계를 설명하는 것이 아니다.

공식 참고: [EA Battlefield 101](https://www.ea.com/games/battlefield/battlefield-6/news/battlefield-101), [EA 멀티플레이 소개](https://news.ea.com/press-releases/press-releases-details/2025/Battlefield-6s-Game-Changing-Multiplayer-and-More-Revealed-During-Blockbuster-Global-Event/default.aspx). 엄폐 거치, 이동과 총기 동작의 연계 등은 이 자료의 공개 동작을 참고한다. 각 게임 버전의 모든 기능을 동일한 수치로 복제했다는 뜻은 아니다.

## 실행 순서와 책임

1. **조준 기반 정리 — 이번에 완료한 범위.** 총과 몸통의 서로 다른 지연 제거, 자유 시점 분리 유지, 서기/앉기와 기존 전투 상태의 회귀 검증. PlayerCharacterWeaponAimView의 표현 책임 안에서 수정한다.
2. **이동/전투 상태 연계 — 기본 구현.** ActionPolicy로 달리기/점프/공격/장전/소생의 경쟁을 제한했다. 방향별 이동 애니메이션과 추가 전환 정교화는 남아 있다.
3. **자세와 특수 이동 — 동작 기반 구현.** Stance를 세 자세로 확장하고 Traversal로 슬라이딩/통과 경로를 분리했다. 전용 모션·지형별 완성도는 남아 있다.
4. **총기 확장.** 장비별 데이터와 교체 상태를 분리하고 Magazine/MeleeAttack/Projectile의 기존 책임을 유지한다. 실제 반동은 게임플레이 조준 정책과 표현 반동을 구분한다. 새로운 판정은 아군 더미 발사자와 적/중립/아군 더미에서 먼저 검증한다.
5. **생존·소생·HUD — 기본 구현.** Health 정책 계약, LifeState, Revive, HUD/표현을 분리해 연결했다. 일반 상호작용·장비·보병 소리는 남아 있다.
6. **환경 이동·탑승 확장·네트워크.** 권한과 취소/복구 규칙을 먼저 확정하고 앞 단계의 상태를 연계한다. 네트워크는 로컬 기능 완료와 별개로 검증한다.

각 단계의 완료 조건은 코드 존재가 아니라 실제 씬 동작, 상태 충돌/취소/복구, 기존 검사 통과, 필요한 애니메이션/오디오 연결이다. 계획 항목은 완료 항목으로 표시하지 않는다.

## 외부 에셋 활용 진행 (2026-10-28)

포트폴리오의 모션은 외부 에셋을 우선 활용하고, 입력·이동/충돌·전투 판정·상태 전환은 프로젝트 코드로 연결한다. 기존 Starter Assets/KayKit/Quaternius/Rokoko 모션을 유지하면서 이번에는 Quaternius의 일반 앉기 반복 클립을 조종석에 연결했다. 탑승/하차 과정 자체의 모션은 아직 없다. 착석 수명/복구 및 기존 기능을 포함한 제품 PlayMode 119/119가 격리 Unity에서 통과했다.

포복 후보 KayKit Crawling은 렌더상 동작 종류와 지면 접촉이 맞지 않아 제외했다. 기존 포복 코드와 수치는 유지한다. 다음 모션 확보 순서는 낮은 군인식 포복 → 슬라이딩/장애물 통과 → 전용 총 타격·소생·승하차다. 모든 기능을 완성했다고 표시하지 않는다. 파일별 변경과 외부 모션/직접 구현 경계는 [이번 기록](PortfolioExternalAnimationChanges.md)에 정리했다.
